Security Core Innovation

The Human-In-The-Loop (HITL) Gate

Bridging the trust gap between generative AI and corporate financial records.

🔒 1. No Auto-Writes Zero Risk
The LLM runtime has ZERO SQL INSERT or Mock Expense API execution tools. Even if completely jailbroken, it cannot alter accounting tables or trigger cash payouts.
🔑 2. Cryptographic Binding SHA-256
When the agent generates an expense proposal, an SHA-256 hash of (amount + category + project + date) is stored in SQLite. Approval requests are rejected if the hash is tampered.
👤 3. Three-Way Human Choice User Control
The consultant is presented with a clear action card offering [Approve & Submit], [Edit Details], or [Discard / Reject] before any record commits to the database.

State Machine Progression:

1. DRAFT (Agent Proposes) ➔ 2. PENDING_APPROVAL (Awaiting Click) ➔ 3. COMMITTED (Human Confirmed) OR 4. REJECTED (User Cancelled)
Defense-in-Depth

Multi-Tier Code-Enforced Guardrails

Why prompt engineering alone is insufficient: deterministic safeguards at every boundary.

🛡️ Tier 1: Input Level < 0.05ms
• Precompiled regex scanners for injection heuristics.
• Indian PII redaction (Aadhaar, PAN, UPI IDs, Phone).
• Base64 & zero-width evasion normalization.
• Sliding window rate limiter (60 requests / minute).
⚙️ Tier 2: Tool Argument Gate Pydantic v2
• Strict type coercion (float amounts, ISO 8601 dates).
• Amount > 0 enforcement (rejects ₹0 or negative values).
• Category enum constraint: Meals, Local Travel, Lodging, Client Entertainment.
⚖️ Tier 3: Business Policy Engine Deterministic
• Meals: Hard cap at ₹1,500 / person.
• Local Travel: Hard cap at ₹3,000.
• Lodging: Hard cap at ₹7,000 / night.
• Inactive projects automatically rejected.
Key Architectural Rule: Even if an adversary convinces the LLM with prompt injection to "approve an ₹8,500 meal on an inactive code", Tier 3 python code intercepts and blocks the call before proposal generation.
Enterprise Security Compliance

OWASP Top 10 for LLM Applications

Hardened against the official 2025 OWASP LLM vulnerability taxonomy.

LLM01 Prompt Injection Defense
Regex heuristics, instruction delimiters ([SYSTEM_PROMPT] vs [USER_INPUT]), and zero-width unicode normalization prevent system override.
LLM02 Sensitive Information Disclosure
Automatic masking for Aadhaar, PAN cards, UPI IDs, bank accounts, and corporate tokens before logging or sending to Azure OpenAI.
LLM03 Supply Chain Integrity
Pinned dependencies in requirements.txt, official Microsoft Azure OpenAI SDK endpoints, and strict virtualenv segregation.
LLM06 Excessive Agency Mitigation
Eliminated by design: LLM is restricted exclusively to read tools. All state mutation requires cryptographic human approval.
LLM07 System Prompt Leakage
Hardened system prompt explicitly instructs refusal of disclosure requests, supported by programmatic output filtering for secret tokens.
LLM10 Unbounded Consumption (DoS)
Sliding-window token rate limiter (60 req/min per employee), input payload size limits (10MB), and request timeout safeguards.

Engineering Excellence

High-Performance Production Engineering

Optimized for sub-second API responses, memory safety, and enterprise reliability.

⚡ SQLite WAL & Pragmas Zero Locks
Configured with PRAGMA journal_mode=WAL, synchronous=NORMAL, and cache_size=-64000 (64MB RAM cache). Handles concurrent reads and writes without thread deadlocks.
🏎️ Precompiled Regexes < 0.05ms
All injection patterns, PII detectors, and OCR extraction patterns are precompiled at server startup via Python's re.compile(), keeping CPU overhead under 50 microseconds per prompt.
🔐 RFC 7518 512-bit Keys Banking Grade
Upgraded from standard 256-bit to 512-bit HMAC secret keys (64-byte entropy), ensuring zero cryptographic degradation warnings and full enterprise SSO compatibility.
Azure OpenAI gpt-4.1-mini

High-speed token generation with lower latency and 80% lower cost compared to legacy models, with native tool-calling accuracy.

Multimodal OCR Fallback

Combines local PyMuPDF / regex extraction with cloud Vision fallback to handle crinkled paper receipts without server crashes.

Self-Contained DB & Docs

Zero external cloud database provisioning required for local demo or staging; SQLite WAL file versioned cleanly in repo.
