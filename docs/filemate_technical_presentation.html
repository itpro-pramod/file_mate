SYS-02 • DEPENDENCY ARCHITECTURE

Specialized Python Packages (Engineering Justification)

Only specialized, high-leverage libraries are integrated. Common general-purpose libraries are minimized to prevent bloat, supply chain attack surface, and deployment overhead.

langgraph (>=0.2.20) State Machine Core

Why Selected: Replaces nondeterministic, black-box agent loops with a cyclic, typed, directed state graph (`StateGraph`). Enables explicit conditional routing edges, step-by-step checkpointing, and deterministic guardrail checkpoints between LLM reasoning steps.

Alternative Rejected: Plain LangChain `AgentExecutor` was rejected because it executes autonomous tool calling loops without intermediate validation gates or deterministic state transition control.
langchain-openai & langchain-core Provider Abstraction

Why Selected: Provides clean interface decoupling for LLM provider switching (`BaseLLMProvider`) supporting Azure OpenAI (`gpt-4o-mini`) and public OpenAI (`gpt-4.1-mini`) with seamless structured output schemas.

Engineering Role: Implements retry policies, timeout configurations (45s cap), and standardized `ChatMessage` data formats.
rapidocr-onnxruntime (>=1.2.3) Local Offline OCR

Why Selected: Lightweight ONNX runtime cross-platform OCR engine. Zero external cloud API calls, zero cost per receipt, and 100% data residency privacy (PII never leaves localhost during OCR). Runs in <350ms on CPU.

Alternative Rejected: `pytesseract` requires system binary C++ dependencies (`tesseract-ocr`), while cloud vision APIs (AWS Textract, Azure Document Intelligence) leak confidential financial receipts to external vendors.
pypdf (>=5.0.0) Dual-Phase Extraction

Why Selected: Fast pure-Python PDF parser with native support for embedded digital text layer extraction and embedded scanned image isolation (`page.images`) for feeding directly into RapidOCR.

Engineering Role: Extracts embedded text instantly (<10ms) without running CPU OCR unless the PDF is a flat scanned document.
pydantic (>=2.9.0) & pydantic-settings Rust Schema Enforcement

Why Selected: Rust-compiled validation core provides sub-millisecond serialization and strict type checking. Enforces structured LLM output schemas (`ExpenseExtraction`) and environment configs (`BaseSettings`).

Engineering Role: Prevents malformed LLM responses from causing runtime NullPointer exceptions downstream in database or calculation layers.
sqlalchemy (>=2.0.35) & alembic (>=1.13.3) Typed ORM & Migrations

Why Selected: SQLAlchemy 2.0 unified typed syntax with `Mapped[...]` attributes. Completely eliminates raw SQL string concatenation, guaranteeing 0% SQL injection vulnerability. Alembic handles reproducible database schema revisions.

Engineering Role: Configured with enterprise WAL mode and 5,000ms busy timeouts for robust multithreaded SQLite operations.
pyjwt (>=2.9.0) RFC 7518 Token Auth

Why Selected: Enterprise HMAC-SHA256 JWT encoding/decoding. Extracts user identity directly from the cryptographically verified `sub` claim, binding employee ID (`EMP001`) to the execution context and preventing identity spoofing.

Security Impact: The LLM is never trusted to determine who the user is; identity is enforced at the HTTP gateway level.
bcrypt (>=4.2.0) Adaptive Key Derivation

Why Selected: Hardware-resistant password hashing using salted Blowfish key derivation function. Protects stored employee credentials against offline rainbow table and GPU dictionary attacks.

Engineering Role: Generates unique per-user salts with configurable work factors (12 rounds) for Brightpath authentication.

SYS-05 • SECURITY TOPOLOGY & ACCESS CONTROL

Read Path vs Write Path Architectural Separation

Physical separation of concern: read tools execute without side effects to gather deterministic ground-truth, while write actions are quarantined behind the Human-in-the-Loop gateway.

Read Path: Direct Context Retrieval Zero Side-Effects

The agent invokes read-only tools to retrieve policies, verify project status, and check submitted history. Because read operations never mutate financial state, they execute in-process without user interruption.

SYS-06 • CRYPTOGRAPHIC INTEGRITY & HITL

Human-in-the-Loop (HITL) & Two-Phase Commit

Cryptographic assurance of human agency: PendingAction records are bound to canonical SHA-256 payload hashes to prevent unauthorized in-flight data manipulation.

Two-Phase Commit Protocol RFC Standard

1. Prepare Phase:

  • Agent validates parameters against corporate policy rules.
  • Calculates canonical SHA-256 hash:
    compute_payload_hash(payload)
  • Persists `PendingAction` with status PENDING and 10-minute expiry.

2. Commit Phase:

  • Human reviews the proposed confirmation card in React UI.
  • User selects: Approve, Edit, or Reject.
  • `ApprovalService` re-computes the hash. If mismatched: PayloadTamperedException.
  • Only after hash verification is the Mock API write executed!

SYS-07 • COMPUTER VISION & INGESTION

Multimodal Document Ingestion & Local ONNX OCR

Dual-phase fallback parser combining pypdf digital text extraction with RapidOCR ONNX runtime for offline, CPU-accelerated scanned receipt reading.

Dual-Phase Extraction Architecture Zero-Leakage OCR
  1. Multipart Upload: File validated for size and type (`.pdf`, `.png`, `.jpg`). Saved to `backend/uploads/receipts/` with sanitized UUID prefix.
  2. Phase 1 (Digital PDF Layer): `pypdf.PdfReader` examines page text streams. If native fonts and text exist, text is parsed in <15ms.
  3. Phase 2 (Scanned Image Extraction): If PDF has zero text layer, `page.images` are extracted in memory and dispatched to `RapidOCR`.
  4. Phase 3 (Image OCR): For flat images, the singleton `RapidOCR()` instance evaluates text blocks via ONNX Runtime without external network overhead.
  5. Phase 4 (Delimiter Quarantine): OCR output is wrapped in Markdown triple quotes (`"""..."""`) before feeding to LLM to prevent prompt injection.

SYS-09 • CRYPTO & PERFORMANCE TUNING

Cryptographic Security & SQLite Concurrency Tuning

Enterprise hardening: 512-bit HMAC signing keys, zero SQL injection, and high-concurrency SQLite WAL tuning.

Cryptographic Hardening RFC 7518 Compliant
  • 512-bit JWT Secret: Upgraded HMAC-SHA256 secret keys to 64-byte high-entropy hex strings conforming strictly to RFC 7518 Section 3.2.
  • Session Identity Binding: User identity is derived exclusively from the verified JWT `sub` claim. Prompts cannot inject or override `employee_id`.
  • Salted Blowfish Credentials: Passwords hashed with `bcrypt` (12 rounds) preventing rainbow table attacks.
  • Canonical Payload Hashing: Strict JSON sorting with SHA-256 for approval state tamper detection.

SYS-12 • ARCHITECTURAL SUMMARY

Summary & Core Architectural Invariants

The key technical principles that guarantee safety, determinism, and enterprise readiness in FileMate.

1. State Machine Determinism

LangGraph 13-node explicit DAG prevents uncontrolled reasoning loops. Every state mutation is typed, serialized via Pydantic v2, and bounded by timeouts.

2. Zero Autonomous Writes

The model possesses no tool capable of modifying production financial records. Write tools solely stage immutable `PendingAction` records awaiting human sign-off.

3. Cryptographic Tamper Defense

Canonical JSON SHA-256 payload integrity guarantees that the exact expense approved on screen matches what executes against the API to the byte.
